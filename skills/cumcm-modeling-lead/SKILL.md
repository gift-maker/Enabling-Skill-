# 国赛人机协同建模

## 核心定位

本 Skill 的核心是帮助全队设计并选择**完整模型方案**，不是从固定算法清单里自动挑一个名称。完整方案包括数据单位、标签或状态定义、变量与特征、数学关系、目标与约束、求解或预测算法、决策规则、不确定性、解释和验证。

全队都是建模者。思路负责人维护全题逻辑和模型裁决，计算负责人维护数据、代码和复现，论文负责人维护表达、图表和一致性；每名队员都应能说明模型为何成立、什么证据支持、何时失效。

AI 可以拆题、生成单模型与组合方案、主动反驳、设计实验、运行比较和提出有条件的推荐。AI 不得仅凭模型名称、单次指标第一或自动选模器冻结主模型。关键题意、现实目标、错误代价、核心假设、候选范围、组合结构和最终模型由建模手确认。

## 面向全队的沟通

开题、模型变化、长计算开始和关键结果出现时，输出一张已经填写的中文说明卡：

```text
现在做到：
这一步要解决：
为什么现在做：
我们已有：
这一步产出：
怎样算完成：
下一步：
```

说明卡不得以空白模板作为答案。已知内容写具体事实；暂时未知时写清“未知内容、未知原因、怎样查清”。初始化脚本产生的占位说明只是内部脚手架，读取题面后必须改写，不能原样交付。

讲模型时使用：

```text
现实问题 → 输入与输出 → 问题结构 → 完整模型模块
→ 候选方案与组合关系 → 假设和约束 → 比较证据
→ AI建议与反对理由 → 建模手裁决 → 失效边界
```

专业词第一次出现时使用“中文（英文或缩写）”，之后优先中文。先讲现实含义，再给公式；公式后说明含义和单位。

## 默认产物

新项目默认只维护：

- `全队建模记录.md`：当前进度、题目事实、逐问结构、模型决策、验证、关键决定和下一步；
- `AI使用记录.md`：记录 AI 提议、全队取舍和人工核验；
- 题面、数据、建模与代码、结果和论文目录。

不创建大量空登记表。同一决定只保留一个面向全队的权威位置；机器运行记录按需生成。已有旧版合同或总控文件时继续读取，不重复创建。

## 四层流程

完整开始时读取 [全队工作流](references/全队一体化工作流.md)。需要设计、组合或选择模型时，以 [模型决策中心](references/模型决策中心.md) 为主入口。

### 第一层：题目与数据事实

1. 完整阅读题面和全部附件；
2. 明确每一问的交付物和跨问依赖；
3. 确认每行数据代表的对象、时间、空间和事件；
4. 区分题目事实、数据发现、领域依据、建模假设、设计选择和未知项；
5. 对每问写清现实目标、输入、输出、单位、硬条件和错误代价。

先独立形成题意和数据结构，再查优秀论文，防止被现成模型带偏。

### 第二层：模型决策中心

模型选择是贯穿解题的循环：

1. **识别结构**：判断描述、解释、预测、评价、决策或机理任务，检查时间、空间、网络、分组、重复、类别不平衡、不确定性和硬约束；
2. **拆分模块**：定义数据单位、标签/状态、输入、变量、参数、关系、目标、约束、算法、决策规则、解释和验证；
3. **广泛生成**：AI 从简单基线、统计模型、数据驱动模型、机制模型、优化模型及合法组合中生成结构不同的完整方案，不受预设的少数算法名限制；
4. **反驳初筛**：逐个说明进入理由、核心假设、数据要求、预期增益、失败风险、淘汰证据和降级路线；
5. **建模手初审**：建模手修改现实目标、错误代价、候选、组合接口和进入实验的范围；概念搜索可以广，实际原型只保留有证据价值且赛时可运行的少数方案；
6. **公平实验**：在相同数据口径、切分、指标和适当预算下运行小闭环，比较样本外表现、稳定性、解释性、约束满足、计算成本和相对基线增益；
7. **有条件推荐**：AI 报告当前推荐、反对理由、最强竞争方案、推荐会改变的条件和尚未完成的验证；
8. **人工裁决**：状态保持“待建模手裁决”，直到建模手明确选择、退回或冻结。未冻结方案不得作为最终模型进入论文、摘要或终稿图。

选型时按需读取 [模型选型树](references/模型选型树.md)、[模型选择与整合协议](references/模型选择与整合协议.md)、当前题型的 [算法索引](references/算法索引.md) 和 [计算能力矩阵](references/计算能力矩阵.md)。这些资料用于扩展和审查候选，不替建模手自动作决定。

完整赛题冻结路线前，读取 [优秀论文资料路由](references/优秀论文资料路由.md)，限时检索本地摘要语料，记录结构对应、可迁移方法、不可照搬处和对候选的实际影响。至少保留一个从本题结构独立推出的强候选。

### 第三层：实现与验证

模型方案通过建模手初审后再实现：

1. 用小样本或缩短范围跑通“读取—核心计算—保存—回代”；
2. 运行廉价审计基线，检查方向、数量级、接口、约束和复杂方案的真实增益；
3. 使用相同数据口径和评价目标公平比较；不能在同一数据上完成选模、调参并报告最终性能；
4. 预测与分类检查正确对象上的样本外误差、类别不平衡、阈值、校准和稳定性；优化检查全部硬约束、上下界和求解状态；评价检查权重含义和扰动；机理与仿真检查守恒、边界和收敛；预测若只是决策输入层，还要检查最终决策质量、风险、约束满足和稳健性；
5. 以题意相关的多维任务增益裁决复杂方案，不以 CV、RMSE、NLL、Brier 等预测指标单独否决；
6. 新证据若改变数据单位、标签、假设、目标、约束或模型结构，未冻结方案退回模型决策中心；已冻结方案只有达到解冻条件才退回，并记录影响范围、作废结果和需要重跑的部分；
7. 连续失败两次时停止盲目重试，判断属于环境、数据、实现、数值还是模型问题。

进入每个递进子问题时都重新识别结构；第三问是高优先级检查点，但不是唯一触发点。若相较上一问新增离散决策、组合约束、资源配置、时序、风险或不确定性，重新判断本问是统计/预测、决策/组合优化，还是“统计 + 决策优化”。题目出现“选择哪些、如何分配、如何安排、最优时点、分组、至少/至多、整数数量、多阶段、路径、调度、成本最小、收益最大、风险最小”等要求时，优先检查决策变量和组合约束。不得硬编码“第三问一定是 NP-hard”；只有出现相应结构时，才提高 MILP、MINLP、CP-SAT、动态规划、网络优化或成熟启发式路线的优先级。

统计与决策串联时按“统计估计/风险建模 → 定义决策变量 → 建立约束 → 构造目标函数 → 求最优方案”推进。预测模型只是决策输入层时，预测指标只能评价输入层，不能单独裁决整套方案。

多维任务增益把预测价值、题意回答能力、解释价值、决策价值、风险分层、约束满足、稳健性和不确定性处理作为候选维度池；只按题意选取与当前方案角色相关的维度，不要求每个候选机械完成八项审核。预测指标未提升但其他相关维度有实质增益时保留方案并降低表述强度，例如“预测性能与基线接近，但能纳入新增因素并改善风险分层或决策支持”；只有相关主要维度均无明显增益时才退回简单方案。

正式结果出现前读取 [证据链与独立验证](references/证据链与独立验证.md)，由未主做该部分的队员换人复核。冻结模型只有出现数据泄漏、目标定义错误、核心约束违反、明显计算错误、模型结构失效，或修正后可能改变主要结论时才解冻；解冻时保存旧版、标记失效产物并重新验证受影响链路。

### 第四层：论文与交付

论文只使用已经冻结的模型和真实验证结果。每一问交付现实任务、完整模型结构、选择依据、公式与约束、输入输出、核心结果、验证、敏感性、结论边界和复现位置。

结果冻结后**必须**进入 [绘图决策中心](tools/figure/SKILL.md)，再允许论文、摘要或交付引用该问结果。每问必须先写入 [终稿图表交付协议](references/终稿图表交付协议.md) 的图表任务卡，并至少交付一张能直接支撑该问主结论的结果图；优化、评价或决策题还必须交付一张解释“方案为何成立或何时切换”的比较、敏感性、稳健性或物料/状态流图。不得用只有表格或文字的冻结结果直接进入论文。

- 所有论文图先强制走 SciPilot：数据剖析、图表契约、按最终尺寸绘制、自动审计和人工视觉回审；
- 每问从图表任务卡中明确一张“核心终稿图”；该图必须在模型已冻结后再走 Nature Figure 的终稿增强、PDF/SVG 导出与字体/碰撞审计；
- 流程图、模型架构图和思维导图使用 `tools/drawio/SKILL.md`，不以数据图代替结构图；
- 图表任务卡、源数据、生成脚本、PNG/SVG/PDF、审计结果和图表—结论映射缺一不可；缺少任一项，该问状态只能是“已冻结、未完成图表交付”，不能进入论文包。

图形目的的具体路由：

- 快速探索或诊断图：使用 SciPilot 的“数据与结论先行”轻量路线；
- 论文普通数据图：SciPilot 选图、绘图和视觉回审；
- 每问指定的一张核心终稿数据图：先由 SciPilot 确定图型，再使用 Nature 终稿增强与自动审计；
- 流程图、模型架构图和思维导图：使用 `tools/drawio/SKILL.md`。

Word、LaTeX、PDF、Excel 按需读取对应 `tools/*/SKILL.md`。绘图工具不得改变数据、模型、指标或结论。

## 模型决策的强制输出

每次关键选型至少向全队给出：

```text
正在决定：
问题结构：
完整候选方案：
各方案进入理由与淘汰条件：
统一比较口径：
已有证据：
当前推荐及反对理由：
推荐会改变的条件：
尚未解决：
建模手裁决：待确认/通过/退回
模型状态：构想/候选/已跑通/暂定推荐/已冻结/已解冻/已淘汰
```

禁止把自动排序得到的 `best_model`、单次最高指标、训练集拟合度、算法复杂度或优秀论文出现频率直接写成最终模型。代码可以生成推荐排序，但正式预测、终稿图、摘要和结论必须检查人工冻结状态。

严格记录模式在进入上述产物前运行：

```bash
python scripts/model_decision_audit.py registries/项目状态.json --require-frozen
```

当主方案已经完整回答当前题目、核心假设无明显冲突、通过至少一种合适的样本外或稳健性验证、满足全部硬约束、最强备选没有足以改变主结论的明显优势、结果可复现且关键数值已经独立回代检查时，立即冻结并进入下一问。冻结后，轻微问题、额外敏感性、边际改进、更多 CV、Bootstrap、随机种子或备选模型只记作局限或附录，不得自动解冻。

只有数据泄漏、目标定义错误、核心约束违反、明显计算错误、模型结构失效，或修正后可能改变主要结论的严重问题，才允许解冻。正式比赛优先保证所有子问题完整交付；若新增验证预计不会改变模型选择、主要结论、分组、排名或最终决策，停止继续验证。

## 完成标准

- 全队能用自己的话说明每问的现实逻辑、完整模型结构和跨问接口；
- 候选不局限于固定算法名，并审查过必要的单模型或组合结构；
- 每个候选有进入理由、假设、验证和淘汰条件；
- AI 推荐与建模手决定明确分开，最终模型有人工作出的冻结记录；
- 结果来自真实运行，并通过与题型匹配的验证；
- 模型变化可追踪，受影响的代码、结果、图表和后问已重审；
- 论文数字、图表和结论都能回溯到冻结模型与源结果；
- 每问都具有已审计的结果图，优化/决策题另有解释策略选择、敏感性、稳健性或状态流的证据图，且核心图已通过 Nature 终稿审计；
- 时间不足时仍保留一套完整、可解释、可复现、通过基本验证的方案。
