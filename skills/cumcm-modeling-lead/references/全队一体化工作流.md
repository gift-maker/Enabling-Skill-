# 全队一体化工作流

## 唯一主线

全队只维护一条权威链：

```text
题面与附件 → Requirement → 模型合同 → Run → Result → Figure → Claim → Paper
```

聊天、草稿、临时图片和旧运行均不是权威事实源。发生冲突时按上面的顺序向上游追溯，不能通过平均、猜测或改写措辞消除冲突。

## 阶段与负责人

| 阶段 | 建模手 | 编程手 | 论文手 | 独立验证者 | 退出条件 |
|---|---|---|---|---|---|
| S0 题包审计 | 锁定题目、附件、交付物 | 核对文件可读性 | 建论文空骨架 | 检查漏件与歧义 | 题包清单冻结 |
| S1 全题拆解 | 建依赖图和系统边界 | 初查字段与规模 | 建章节映射 | 检查是否漏问 | 每问输入输出明确 |
| S2 M0 模型合同 | 定假设、变量、关系、目标、约束 | 审查可实现性 | 审查可表达性 | 反向质疑 | 建模手能独立复述 |
| S3 数据与基线 | 确认数据口径 | 数据契约、EDA、基线纵切 | 记录可用图表位置 | 查泄漏、单位、异常 | 基线可复现且能回答题目 |
| S4 主模型 | 决定候选取舍和组合 | 实现、真实运行、记录 Run | 只写方法骨架 | 检查公式、约束、收敛 | 主模型完成题型匹配验证 |
| S5 稳健性 | 决定关键情景 | 敏感性、扰动、备选比较 | 准备验证段 | 独立复算与边界测试 | 结论稳定性边界清楚 |
| S6 证据冻结 | 批准结论边界 | 冻结 Result 和图表数据 | 只引用 paper_ready 项 | 审核证据链 | 核心 Claim 均可追溯 |
| S7 论文装配 | 审核逻辑 | 核对数字和代码接口 | 写作、排版、编译 | 一致性审查 | 摘要正文表图一致 |
| S8 评委终审 | 裁决修复优先级 | 修复复现问题 | 修复表达与版面 | Fresh-eyes 审查 | 无开放 P0/P1 |
| S9 提交 | 最终签字 | 打包支撑材料 | 导出论文 | 匿名、规则、AI 披露 | 解压副本复核通过 |

## 交接协议

建模手向编程手交付每问 `模型合同`，至少包含：输入、输出、符号、单位、假设、方程、目标、约束、参数识别、验证、失败条件和降级路线。

编程手向论文手交付 `result_id`、数值、单位、场景、来源 `run_id`、验证状态、图表数据和复现命令。不得用聊天中的数字替代登记值。

编程手在读取附件后更新 `1_数据/data_contract.json`，至少记录源文件、字段、类型、单位、缺失、范围、唯一性、时间顺序、分组/空间结构、泄漏风险和未知项；建模手确认后才作为正式数据口径。

论文手向验证者交付论文、图表、登记表和支撑材料。验证者只报告证据缺口和最小修复面，不擅自创造数据或改变模型。

## 决策门

下列事项必须由建模手确认：

- 题目目标或答案口径变化；
- 新增或删除关键现实约束；
- 会改变主结论的假设；
- 使用无法从数据识别的参数；
- 主模型或模型组合结构变化；
- 将带误差的上游结果当作下游确定输入；
- 缩小结论边界仍无法解决的证据缺口。

代码结构、绘图样式、等价求解器、已确认范围内调参和局部修复不重复请求确认。

## 时间降级

时间不足时按以下顺序保留：

1. 直接回答所有子问；
2. 可复现基线和硬约束可行性；
3. 核心主模型与关键验证；
4. 结果、单位和全文一致性；
5. 美化、复杂模型和非关键附加实验。

未经验证的高级模型不得挤掉已验证基线。
