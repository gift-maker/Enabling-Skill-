# 证据链与独立验证

## 状态定义

所有关键项只能使用以下状态：

- `planned`：计划中；
- `exploratory`：探索结果，不可进摘要与结论；
- `candidate`：候选结果，尚未完成验证；
- `validated`：完成指定验证，但尚未冻结；
- `paper_ready`：数据、运行、验证、单位、场景和结论边界均冻结；
- `rejected`：证据不足或模型被淘汰；
- `superseded`：被更新结果替代。

程序运行成功不能自动获得 `validated`；图片生成成功不能自动获得 `paper_ready`。

状态提升必须附检查记录，使用 `scripts/update_evidence_status.py` 更新并写入 `registries/status_changes.csv`。状态工具只登记人工判断，不能替代实际验证。

## 五本账

项目的 `registries/` 至少包含：

1. `run_ledger.csv`：谁在何时用什么输入、代码、参数和种子执行了什么命令；
2. `result_registry.csv`：正式数值、单位、场景、来源 Run 和验证状态；
3. `claim_ledger.csv`：论文主张、适用边界及其结果/图表/公式/来源证据；
4. `figure_evidence.csv`：图表文件、源数据、支持的 Claim、单位、场景与视觉检查；
5. `issue_ledger.csv`：P0–P3 问题、修复责任人和状态。

## 反幻觉规则

- 题目事实必须指向题面页码、段落或附件字段；
- 数据发现必须指向实际分析脚本和 Run；
- 参数必须标注为题目给定、数据估计、文献依据或设计选择；
- 文献元数据、DOI、作者和结论必须核验原文；
- 无法识别的量保留为未知项，不能用“典型值”静默填充；
- 相关性不能自动写成因果性；
- 优化求解器返回 success 不等于现实约束全部满足，必须回代；
- 训练集拟合优良不能代替样本外验证；
- 漂亮图表不能代替源数据和结论证据；
- 论文写作不能新增未登记的数值、模型、参数或结论。

## 独立验证矩阵

| 层次 | 必查内容 | 常用手段 |
|---|---|---|
| 题意 | 是否回答原问、交付物是否完整 | Requirement 对照 |
| 数据 | 字段、类型、缺失、异常、重复、时间顺序、泄漏 | 数据契约、Pandera、抽样复核 |
| 数学 | 量纲、符号、特例、边界、解析关系 | 手算、SymPy、单位库 |
| 统计 | 切分、假设、残差、区间、效应量 | statsmodels、交叉验证、Bootstrap |
| 优化 | 变量域、约束回代、可行性、最优性证据 | 小规模精确解、上下界、多起点 |
| 仿真 | 守恒、步长、收敛、随机误差 | 网格/步长收敛、多种子 |
| 稳健性 | 参数、数据、模型和情景变化 | 单因素扰动、SALib、消融、备选模型 |
| 跨问 | 上游误差是否进入下游 | 区间、情景、鲁棒或蒙特卡洛传播 |
| 复现 | 输入、代码、环境、命令和输出 | Run 账本、哈希、干净目录重跑 |
| 论文 | 数值、单位、场景、图表和措辞 | Claim/Result/Figure 对照 |

## Fresh-eyes 审查

正式论文完成后，验证者只读取题面、论文、冻结登记表和提交包，不读取作者的聊天解释。按严重度记录：

- `P0`：编造、题意错误、规则/匿名违规、缺少必答内容；
- `P1`：核心结论无证据、硬约束违反、不能复现、数字冲突；
- `P2`：验证薄弱、边界不清、创新无基线、图表难读；
- `P3`：不影响证据的局部表达或排版问题。

开放的 P0/P1 阻塞最终提交；P2 必须修复或由建模手明确接受风险；P3 不得挤占关键验证时间。

## 最小反方问题

独立验证者必须回答：

1. 当前模型是否解决了题目要求的那个问题？
2. 最强假设若不成立，哪个结论先失效？
3. 哪个参数最缺乏证据，能否从数据识别？
4. 是否存在数据泄漏、单位错位或索引错位？
5. 主模型相对基线的增益是否真实且与题目有关？
6. 输出是否满足全部硬约束和边界条件？
7. 哪个正文数字无法从 Run 复现？
8. 哪个结论的措辞强于证据？
