# 国赛建模 Skill 中文使用说明书

## 一、定位

`cumcm-modeling-lead` 用于国赛及相近数学建模比赛。它帮助全队与 GPT 共同设计、组合、反驳和验证**完整模型方案**，再由建模手作出最终选择。

完整方案不只是算法名，而是：

```text
现实对象和边界
→ 数据单位与标签/状态
→ 输入、变量和参数
→ 数学关系、目标和约束
→ 求解或预测算法
→ 决策规则、阈值与误差传播
→ 解释方法
→ 验证和失效条件
```

GPT 负责拆题、扩展候选、主动反驳、设计实验、运行比较和提出有条件推荐；建模手负责现实目标、错误代价、关键假设、候选范围、组合结构和最终模型裁决。

## 二、七条强规则

1. AI 推荐不等于最终选择。
2. 单次指标最高不等于最佳模型。
3. 代码中的 `best_model` 只能表示当前排序第一的候选。
4. 没有“建模手裁决：通过”和“模型状态：已冻结”，不能生成正式预测、终稿图、摘要或最终结论。
5. 新证据推翻数据单位、标签、假设、目标或约束时，模型必须解冻并返回修改。
6. 每个关键节点用中文说明当前在做什么，不能输出空白模板。
7. 论文只使用真实运行、经过验证并已冻结的结果。

## 三、开始使用

开始新题：

```text
使用 $cumcm-modeling-lead 从头处理这道赛题。
完整读取题面和附件，说明每一问的现实目标、输入、输出、约束和依赖。
然后和我讨论完整模型结构、单模型与组合方案、假设、淘汰条件和验证。
AI可以推荐，但保持待建模手裁决，未经我确认不要冻结模型。
```

继续已有项目：

```text
使用 $cumcm-modeling-lead 继续当前项目。
先读取全队建模记录、代码和真实结果，告诉我当前模型状态、
已经确认的决定、尚未解决的问题和下一项需要我参与的建模决定。
不要重复初始化，不要覆盖已验证结果。
```

只讨论模型：

```text
使用国赛建模 Skill，只进入模型决策中心，暂时不要写代码。
先根据问题结构生成完整的单模型和组合方案，
逐个给出支持理由、反对证据、淘汰条件和最小验证实验。
```

## 四、关键节点说明卡

开题、模型变化、长计算和关键结果出现时，Skill 输出：

```text
现在做到：
这一步要解决：
为什么现在做：
我们已有：
这一步产出：
怎样算完成：
下一步：
```

每项必须填入当前题目的真实内容。暂时不知道时，应写明未知项、未知原因和查证方法。初始化脚本产生的占位内容不是建模答案，读取题面后必须更新。

## 五、第一层：题目与数据事实

先确定：

- 每问实际交付什么；
- 各问怎样依赖；
- 研究对象是一名人员、一次事件、一个地区、一个时刻还是一条记录；
- 输入、输出、时间、空间、单位和范围；
- 题目硬条件；
- 数据发现；
- 建模假设和设计选择；
- 尚未解决的未知项。

推荐指令：

```text
先不要推荐模型。检查题面和全部附件，
按题目事实、数据发现、领域依据、建模假设、设计选择、未知项分类，
再给出全题依赖关系。
```

完成标准：全队不用模型名也能复述每一问的现实任务。

## 六、第二层：模型决策中心

### 1. 拆分完整模型模块

| 模块 | 要决定的内容 |
|---|---|
| 对象与边界 | 对谁、何时、何地建模 |
| 数据单位 | 一行代表什么，重复数据怎样处理 |
| 状态或标签 | 输出怎样定义，是否存在多种口径 |
| 输入与变量 | 哪些可观测，哪些由模型决定 |
| 数学关系 | 线性、非线性、动态、网络、随机还是机理 |
| 目标与约束 | 什么叫好，哪些条件必须满足 |
| 算法 | 如何估计、求解或预测 |
| 决策规则 | 阈值、排序或行动怎样确定 |
| 不确定性 | 误差怎样报告并传到后问 |
| 解释与验证 | 什么证据支持，什么结果会推翻 |

### 2. GPT 广泛生成方案

候选可以包括：

- 简单和可解释基线；
- 统计或机器学习模型；
- 机理或优化模型；
- 串联方案；
- 并联比较；
- 集成预测；
- 分层模型；
- 机制与数据融合；
- 评价与优化衔接。

概念搜索可以广，实际实验由建模手缩小到少数结构不同、有验证价值、能在比赛时间运行的方案。

推荐指令：

```text
不要只列算法名称。把每个候选写成完整模型方案。
说明真实作用、假设、数据要求、模块接口、预期增益、
反对证据、淘汰条件和失败后的降级路线。
```

### 3. 建模手实时修改

可以直接说：

```text
把发现失业人员设为主要目标，整体平衡准确率作为辅助指标。
```

```text
保留逻辑回归作为解释基线，随机森林作为非线性候选，
增加一个分类变量友好的提升树方案。
```

```text
暂时不要集成。先检查各模型错误是否互补，
融合不能稳定超过最强单模型就淘汰。
```

GPT 应把修改写回模型决策记录，并说明影响哪些代码、结果、后问和论文内容。

### 4. 公平实验

候选之间保持：

- 相同数据口径和评价对象；
- 相同训练验证边界；
- 相同主要指标；
- 合理且可比较的计算预算；
- 相同的数据泄漏防线。

同时报告：

- 主指标和辅助指标；
- 多次划分或多随机种子的波动；
- 关键类别或硬约束；
- 阈值和校准；
- 敏感性与稳定性；
- 解释性；
- 运行和复现成本；
- 相对简单基线的增益。

### 5. 推荐与冻结

GPT 推荐格式：

```text
当前推荐：
推荐依据：
相对基线的增益：
最强竞争方案：
反对当前推荐的证据：
推荐会在什么条件下改变：
未完成的验证：
建模手裁决：待确认
```

建模手确认格式：

```text
冻结方案：
保留的基线和强备选：
冻结依据：
关键假设和适用边界：
建模手裁决：通过
模型状态：已冻结
允许正式预测/求解：是
允许进入论文和终稿图：是
```

如果不同意，可回复：

```text
不冻结。当前差异没有超过验证波动，
先修改评价目标并补充阈值敏感性。
```

## 七、第三层：实现与验证

方案通过初审后：

1. 用小数据或缩短范围跑通最小闭环；
2. 用廉价基线检查方向、数量级、接口和复杂方案增益；
3. 公平比较主候选和强备选；
4. 完成全量计算；
5. 执行题型验证；
6. 由另一名队员换人复核。

| 题型 | 重点验证 |
|---|---|
| 预测和分类 | 正确对象上的样本外误差、类别不平衡、阈值、校准、稳定性 |
| 优化 | 硬约束回代、可行性、上下界、最优性状态、多起点 |
| 评价 | 指标方向、价值含义、冗余、权重和排名敏感性 |
| 机理与仿真 | 守恒、量纲、边界、步长或网格收敛 |
| 统计推断 | 研究设计、分布、相关性、效应量、区间和稳健性 |
| 聚类 | 稳定性、现实解释和外部验证 |

程序成功运行只说明实现能执行，不说明模型正确。

## 八、模型修改和解冻

发现新问题时记录：

```text
修改内容：
修改原因和证据：
影响的问题和模型模块：
需要重跑的代码与实验：
已经失效的结果、图表和文字：
保留的历史版本：
修改后的验证计划：
模型状态：已解冻/待确认
```

只返回受影响的最早阶段。旧结果可以保留对照，但不能继续进入论文。

## 九、第四层：绘图和论文

### SciPilot 默认绘图

```text
分析数据
→ 明确图要支持的结论
→ 推荐图型和备选
→ 说明不推荐图型
→ 绘图
→ 自动检查
→ 实际查看
```

调用：

```text
使用 $cumcm-figure 绘制问题二模型比较图。
先读取冻结结果，说明图要支持什么结论，
再根据数据结构推荐图型，不要默认画柱状图。
```

### Nature 核心终稿增强

只用于少数已冻结核心图：

- 源文件预检；
- PDF 最小字体检查；
- 文字和图形碰撞检查；
- 多面板对齐检查；
- PNG、SVG、PDF 导出；
- 人工查看。

调用：

```text
这张图已经对应冻结模型和结果。
先用 SciPilot 确认图型，再做 Nature 终稿增强，
保留源数据、脚本、PNG、SVG、PDF和审计结果。
```

流程图、模型架构图和思维导图使用 Draw.io。

python scripts/init_competition_project.py D:/cumcm/projects/2026-C --competition CUMCM --problem C --strict

## 十一、项目文件

```text
题面与附件/        原始题目和附件
数据/              清洗数据、特征数据和外部数据
建模与代码/        可运行程序
结果/              候选结果、验证结果和冻结结果
论文/              正文、表格、图和参考文献
全队建模记录.md    全队当前共识和模型裁决
AI使用记录.md      AI提出内容、全队取舍和人工核验
```

默认只维护必要文件；严格模式再增加运行、结果、图表和论文结论登记。

## 十二、华中杯 C 题示例

旧代码曾在四个候选中按平衡准确率把随机森林排在第一。新版 Skill 应写成：

```text
当前推荐：随机森林候选方案
推荐依据：当前交叉验证平衡准确率最高
反对证据：领先幅度较小，失业召回率低于逻辑回归
尚未解决：人员级评价、多随机种子、阈值、校准和提升树对照
建模手裁决：待确认
模型状态：暂定推荐
```

补充验证并由建模手确认前，不能把随机森林写成最终模型，也不能把候选图包装成正式结论。

## 十三、推荐的讨论方式

比赛中可以持续对 GPT 说：

```text
我对这个目的理解为……
这个假设可靠吗？
还有哪些结构不同的方案？
能否把机制模型和数据模型结合？
什么证据可以淘汰这个方案？
这个指标符合现实目标吗？
目标改变后推荐会不会改变？
先做哪个最小实验最有信息量？
我接受、修改或退回这个方案。
```

GPT 应始终说明正在决定什么、已有证据、主要分歧和下一步。最终模型由全队理解并由建模手冻结。
