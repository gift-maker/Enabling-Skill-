# 阶段流程（建模计算与结果交接）

本文件是执行手册，不是论文格式的替代品。所有阶段都服从以下优先级：

```text
真实结果可运行 > 模型与题目匹配 > 验证与复现 > 改进与创新 > 论文排版与美化
```

默认只在三个节点向用户确认：

1. **路线确认**：题意、数据、逐问任务表和候选路线明确后；
2. **关键结果确认**：各问真实计算完成并通过基本验证后；
3. **结果交接确认**：结果包可复现、跨问接口一致、关键数字和图表冻结后。

用户明确要求逐节审核时，才增加审核点。任何阶段都不得用预计值、手工编造值或未收敛值代替真实计算结果。

## 0. 启动与任务表

输入赛题原文、附件、已有代码和交付要求，先完成：

- 核对题目公式、单位、上下标、表格字段和顶层子问题；
- 读取项目 `AGENTS.md` 及其中指定的本地资料和纠错记录；
- 建立逐问任务表：输入、输出、单位、约束、评价指标、问题依赖、待验证假设、结果文件；
- 运行环境和数据预检：Python 包、求解器、文件编码、数据规模、内存和预计耗时；只有用户要求论文整合时才检查 LaTeX 工具；
- 仅按需读取 [模型选型树](模型选型树.md)、[算法索引](算法索引.md) 和对应算法资料，不一次加载全部知识库。

路线确认前只提交题意、风险、计算预算和候选路线，不生成正式论文正文。

## 1. 数据预处理

1. 先列字段含义、单位、时间/空间范围、缺失、异常、重复和泄漏风险。
2. 在小样本或等价小实例上跑通“读取 → 清洗 → 保存 → 复核”。
3. 全量处理时保留清洗前后数量、比例、范围和派生指标。
4. 预测任务先划分训练/验证，再拟合 scaler、encoder 等变换；时序任务不得随机打乱。
5. 保存清洗后的权威数据、数据摘要、处理日志和可复现入口。

## 2. 每道子问题的计算闭环

每问按照以下顺序执行，不为形式机械增加模型：

### 2.1 题型和输出定义

明确本问要回答的结论、决策变量或预测对象、输入输出、单位、约束、评价指标，以及与其他问题的依赖。记录数据不足、不可辨识和外部假设，不能用虚构数据补齐。

### 2.2 模型合同、主方案与廉价审计基线

先按 `建模手总控协议.md` 完成 M0 建模逻辑门，同时确定审计基线、主方案和强备选。基线用于方向与数量级检查，主方案用于处理本题关键结构；二者采用一致的数据口径和评价指标。

先完成主方案的最小纵向闭环：“读取 → 核心计算 → 保存 → 回代检查”。随后执行廉价审计基线，优先采用手算特例、规则方案、简单模型、松弛或短时限求解。

基线用于检查方向是否正确、数量级是否合理、数据和接口是否一致、约束是否满足，以及主方案是否产生有效增益。若基线暴露明显异常，优先检查和修正主方案；否则进入主方案全量计算。

### 2.3 主方案筛选

主方案必须明确解决基线的具体缺陷，并由问题结构、目标和约束、数据规模、不确定性、预计耗时、实现成熟度、诊断能力和复现成本支持。若最小原型不能体现可测量增益、无法解释或运行不稳，切换强备选或保留基线，不继续堆叠模型。

复杂算法必须在全量运行前给出：

- 预计运行时间和内存；
- 依赖库、关键参数和停止条件；
- 随机种子或初始化方式；
- 失败模式；
- 明确的备用路线。

“优秀算法”指适配题目、稳定、可解释、可验证并相对基线有可测量价值的算法，不等于最复杂的算法。

### 2.4 全量运行与结果留痕

统一保存：

- 数据来源、版本和摘要；
- 环境与依赖版本；
- 运行入口、参数、随机种子；
- 运行时间、停止原因和关键日志；
- 中间结果、最佳可行解、最终表格和绘图数据；
- 失败试验及简短原因。

长任务设置最大时间/迭代次数，必要时周期性保存检查点和当前最佳可行解。优化问题保存目标值、约束违反量、求解状态和可获得的最优性差距；预测问题保存训练/验证划分和误差；随机算法在必要时重复运行并报告均值和波动。

### 2.5 题型匹配验证

至少选择与题型对应的验证：

- 预测/分类：留出集或交叉验证、残差、误差分布、基准比较；
- 优化：可行性、约束余量、边界/最优性证据、多初值或对照复算；
- 评价/排序：方向检查、权重扰动、排序稳定性、指标冗余；
- 仿真/微分方程：步长/网格收敛、边界、守恒或稳定性；
- 统计推断：假设诊断、置信区间、效应量和稳健性；
- 聚类/降维：稳定性、轮廓指标、解释方差和实际解释。

验证发现问题时，先区分数据、公式、实现、数值和模型假设问题，再修正或换路线。

### 2.6 结果冻结

结果只有同时满足以下条件才允许写入论文：

- 由当前项目代码真实运行产生；
- 输入、参数、单位和证据路径明确；
- 通过基本正确性与题型匹配验证；
- 与后续问题使用的中间量一致；
- 能从统一入口复现核心结果。

冻结后记录关键数字、表格、图和文件路径。重跑改变结果时，先更新冻结记录，再同步正文、摘要和图表。

## 3. 防卡死与降级

- 全量运行前必须有小规模测试和时间/内存估计；
- 优先解析法、结构化算法、成熟库和成熟求解器，不自写脆弱的复杂求解器；
- 同一路线连续失败两次后停止盲目重试，记录错误并诊断原因；
- 高级方案无法在预算内稳定完成时按顺序降级：简化或近似 → 降维/缩小搜索空间 → 成熟启发式或确定性方法 → 已验证基线；
- 时间不足时保住一套正确、可解释、可验证的完整答案；
- 未运行、未收敛、不可行或无法核验的数字不得写入论文，也不得把失败输出伪装成结果。

## 4. 优秀论文资料的使用（限时、按需）

先依据题目结构形成初步模型合同，再限时检索优秀论文与领域文献。资料用于发现机制、参数依据、候选和验证设计，不替代本题推导，也不阻塞主方案推进或廉价基线检查：

- 写入某个 LaTeX 章节前，读取 [优秀论文写法指南.md](优秀论文写法指南.md) 的对应章节；
- 只有需要章节频率、句式证据或案例时，才读取 [优秀论文语料分析报告.md](优秀论文语料分析报告.md) 的对应小节；
- 写摘要时读取 [摘要写作/摘要写作方法论.md](摘要写作/摘要写作方法论.md)，并执行“起草 → 逐数值核验 → 定稿”；
- 只借鉴章节结构、论证顺序、证据组织和表达方式，不照抄语料，不把语料统计当官方硬要求；
- 每个模型段落都应说明问题元素、模型元素、算法依据、参数/停止条件、真实结果和现实意义。

建议成稿顺序为：

```text
摘要（最后起草）→ 问题重述 → 问题分析 → 模型假设 → 符号说明
→ 数据处理 → 各问建模与求解 → 模型检验 → 模型评价
→ 参考文献 → 附录
```

## 5. 可选的 LaTeX 支持

仅当用户明确要求论文整合时执行本节；建模手交付结果包时跳过。

1. 结果冻结后，按当届官方 LaTeX 模板初始化 `完整论文-LaTeX/`；
2. 用章节文件维护正文，用权威结果文件生成数字、表格和图片；不手工抄写未经核验的数字；
3. 图表只生成服务于比较、诊断、敏感性或结论的图，不凑数量；
4. 关键公式使用原生 LaTeX 数学环境，按需编号并解释符号；
5. 摘要最后写，逐项回查正文、表格和程序输出；
6. 运行 LaTeX 工具的 doctor、真实编译、质量校验和 PDF 视觉抽检；编译失败或存在未解析引用时不得宣称完成；
7. LaTeX 使用与建模结果相同的权威数据和图表，不维护第二套手抄数值。

## 6. AI 使用留痕与提交

每个关键阶段及时向 `PROJECT_ROOT/ai_usage_log.md` 追加真实记录：时间、工具版本、参与内容、提示词摘要、参赛队处置、核验方式和对应文件。不得虚构或事后凭印象补造。

最终是否生成 AI 声明和详情 PDF，以当届全国、赛区和提交系统的最新规则为准。需要时使用 `references/AI使用报告/` 的 LaTeX/PDF 流程；核心建模和问题分析必须如实表述为参赛队主导并逐项人工核验。

## 7. 完成判定

交付前确认：

- 所有子问均有真实运行结果、现实解释和题型匹配验证；
- 统一入口可以复现核心结果；
- 代码、数据、参数、日志、结果、图表、正文和摘要数字一致；
- 结果包已包含关键数字、单位、表格、图、验证证据、运行日志和统一复现入口；
- 用户要求论文整合时，LaTeX 已真实编译且 PDF 经过版面和官方规则检查；
- 当届提交要求、页数、附件和 AI 合规口径已重新核验；
- 若高级方案未完成但基线闭环可靠，明确交付基线及局限；若连可信基线都没有，不能宣称题目完成。
