# 国赛全队建模协作

## 核心定位

全队都是建模者，只是主要分工不同。每名队员都要理解题目要求、模型为何成立、输入输出、关键假设、约束、验证方法和结论边界。

- 思路负责人主要维护全题逻辑和模型选择；
- 计算负责人主要维护数据、代码、求解和复现；
- 论文负责人主要维护表达、图表和前后一致；
- 每一问至少由一名未主做该部分的队员换人复核。

分工不等于知识隔离。不能出现“模型只有思路负责人懂、代码只有计算负责人懂、结论只有论文负责人会说”的情况。

## 默认沟通方式

开题、路线变化、长计算开始和关键结果出现时，给全队一张简短说明卡：

```text
现在做到：
这一步要解决：
为什么现在做：
我们已有：
这一步产出：
怎样算完成：
下一步：
```

说明卡使用日常中文。专业词第一次出现时用“中文（英文或缩写）”，之后只用中文。不要为每个数据清洗、代码修改或求解器调用机械重复说明卡，也不要把阶段代码、文件编号、运行编号和英文状态词堆给用户；机器记录可以保留英文键名。

讲模型时按下面顺序：

```text
现实问题 → 输入 → 输出 → 为什么需要这个模型
→ 模型怎样工作 → 假设和约束 → 怎样判断结果可信 → 何时会失效
```

先讲明白，再给公式；公式后必须补一句现实含义和单位。

## 默认产物：少而清楚

新项目默认只维护：

- `全队建模记录.md`：当前进度、全题依赖、事实与未知、逐问思路、模型选择、关键决定、验证和下一步；
- `AI使用记录.md`：比赛实际使用 AI 时维护；
- 题面、数据、代码、结果和论文所在目录。

不要在开局创建大量空登记表、空报告或重复内容。同一信息只保留一个权威位置。

正式计算开始后，真实运行需要记录输入、代码、参数、随机种子、输出和验证状态；可由脚本按需创建技术记录。进入终稿冻结时，再按需创建结果、图表和论文结论的对应关系。用户要求严格审计、团队规模较大或结果较多时，使用严格记录模式。

已有项目若包含 `建模总控.md`、`模型合同.md`、`术语与符号表.md` 等旧版文件，继续读取，不重复生成；后续可把面向全队的最新结论汇总到 `全队建模记录.md`。

## 七步主流程

完整开始时读取 [全队工作流](references/全队一体化工作流.md)。需要深入审查模型逻辑时读取 [全队建模协议](references/建模手总控协议.md)。

### 第一步：把题读明白

完整阅读题目和附件，回答：

1. 每一问要交付什么；
2. 各问如何连接；
3. 已知信息和未知信息是什么；
4. 数据每一行、每个对象和每个时间代表什么；
5. 哪些是题目硬条件，哪些需要我们自己定义。

先独立形成题意和数据结构，再看优秀论文，防止被现成模型带偏。

### 第二步：把问题变成数学任务

对每一问说清：

- 输入是什么；
- 输出是什么；
- 要解释、预测、评价还是做决策；
- 哪些量已知，哪些要估计，哪些由模型决定；
- 现实要求怎样变成公式或约束；
- 前一问输出如何进入后一问。

将内容分成：题目事实、数据发现、领域依据、建模假设、设计选择和未知项。不得把假设写成事实。

### 第三步：限时比较模型路线

通常提出 2–4 个真正可行的模型族，不机械凑数。先按题目结构、数据、算力和验证能力确定优先级，至少保留：

- 主方案：解决本题最关键的数据或机制结构，优先实现和获得主要算力；
- 强备选：假设不同，用于主方案失败或稳健性检查。
- 廉价审计基线：用于检查方向、数量级、接口和主方案增益，不主导总体路线。

每个候选都用浅显中文回答：

1. 它解决了什么真实问题；
2. 为什么适合当前数据；
3. 需要哪些假设；
4. 数据能否估出参数；
5. 怎样公平比较；
6. 什么证据会淘汰它；
7. 在比赛时间内能否跑完。

模型名称、优秀论文出现频率、训练集拟合度和算法复杂度不能单独证明模型更好。

选型或组合模型时再读取 [模型选择与整合协议](references/模型选择与整合协议.md)、[模型选型树](references/模型选型树.md) 和当前题型对应的 [算法索引](references/算法索引.md)。

### 第四步：主路线讲通后立即做小闭环

主路线确定前，全队应能不用 AI 回答：

- 这问到底要算什么；
- 输入和输出是什么；
- 为什么这样定义目标；
- 每条关键约束来自哪里；
- 为什么主方案比简单基线合适；
- 什么现象会说明模型错了；
- 结果将怎样传给下一问。

只对目标、关键现实约束、会改变主结论的假设、关键数据缺口和主路线变化进行集中确认。已确定路线内的数据清洗、代码结构、等价求解器、调参、诊断和修复继续推进，不反复打断用户。

### 第五步：主方案优先计算

按以下顺序：

1. 检查字段、单位、缺失、异常、重复、时间顺序和数据泄漏；
2. 用小样本或缩短时域先跑通主方案的“读取—计算—保存—回代”，估计全量时间和内存；
3. 跑廉价审计基线，优先使用手算特例、规则方案、简单模型、LP 松弛、短时限求解或对同一方案复评多个情景，检查方向、数量级、数据与接口、约束和主方案有效增益；
4. 若基线暴露明显异常，优先检查和修正主方案；否则进入主方案全量计算，并使用相同数据口径和指标比较；
5. 把主要计算预算用于主方案的结构改进、稳定求解、关键敏感性和验证；基线默认不与主方案使用相同全量时限，通常不超过计算预算的一成；
6. 连续失败两次时停止盲目重试，判断是环境、数据、实现、数值还是模型问题；
7. 主方案超出时间或无法验证时，切换强备选或已验证基线。

准备正式实现前读取 [计算能力矩阵](references/计算能力矩阵.md)。正式数值必须来自真实运行，不用“预计结果”代替。

### 第六步：验证结果，而不只检查代码运行

- 预测和分类：看按正确对象划分的样本外误差、校准、类别不平衡和基线比较；
- 优化：把结果代回全部硬约束，检查可行性、上下界、最优性证据和多起点稳定性；
- 评价排序：检查指标方向、重复信息、权重扰动和排名稳定性；
- 仿真与机理：检查守恒、边界、步长或网格收敛；
- 统计推断：检查分布、相关性、效应量、置信区间和稳健性。

前问结果进入后问时必须传递单位、取值范围和不确定性，不能把带误差的预测静默当成精确常数。

正式结果出现前读取 [证据链与独立验证](references/证据链与独立验证.md)。换一名队员用只读结果进行复核，优先寻找错误。

### 第七步：把可信结果交给论文

论文只使用已经验证的模型和真实数值。每一问给全队一页以内说明：

- 这问做了什么；
- 为什么采用该模型；
- 核心输入、输出、公式和约束；
- 主要结果及现实意义；
- 验证和敏感性；
- 结论可以说到哪里；
- 代码和结果从哪里复现。

结果较多或进入终稿时读取 [论文与图表证据协议](references/论文与图表证据协议.md)，再建立详细对应记录。写作不能创造新数值、新模型或新因果结论。

## 文献与优秀论文

先独立读题并冻结第一版问题结构，再进行限时、定向检索。正式完整赛题优先快速检索 Skill 内最相近的少数优秀论文，提炼结构对应、可迁移方法、验证和不可照搬处；同时保留至少一个从本题数学结构独立推出的强候选。文献用于发现机制、参数依据、成熟模型和验证方法，不得复制其他论文的参数、阈值、分组、性能和结论。

外部检索只在可能改变假设、模型结构、参数依据、候选排序或验证方法时进行，并预先限定时间和问题范围；没有实际决策收益、网络不可用或已进入应急保底时记录理由后停止。需要检索时读取 [论文检索工具](tools/paper_search/SKILL.md)。

## 完成标准

完成不是“生成了很多文件”，而是：

- 全队能用自己的话说明每问逻辑；
- 所有子问都有明确输入、输出和跨问关系；
- 核心假设、公式、目标和约束有来源；
- 结果来自真实运行并通过适合题型的验证；
- 前后问的名称、单位和不确定性一致；
- 论文数字与结果一致；
- 全队知道模型为什么成立、何时失效以及结论适用范围；
- 时间不足时仍保留一套可解释、可复现、通过基本验证的完整答案。
