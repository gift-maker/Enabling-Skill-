# 全队建模协议

文件名为兼容旧版保留，协议适用于全队，不只适用于思路负责人。

## 一、先说人话，再写公式

每问先用一段话回答：

1. 现实中要解决什么；
2. 已知什么；
3. 要求模型决定或估计什么；
4. 为什么现有信息可能够用；
5. 最终怎样判断答案可信。

公式出现后必须解释每个量、单位和现实含义。

## 二、分清六类内容

| 类型 | 含义 | 使用规则 |
|---|---|---|
| 题目事实 | 原题或附件明确给出 | 不能擅自改变 |
| 数据发现 | 对附件真实计算得到 | 数据处理变化后复算 |
| 领域依据 | 经核验资料支持 | 记录来源和适用范围 |
| 建模假设 | 为简化问题而采用 | 说明影响和检查方式 |
| 设计选择 | 阈值、权重、指标或算法选择 | 比较替代方案或做敏感性 |
| 未知项 | 现有证据不能确定 | 不假装已知 |

## 三、每一问的最小逻辑

共享记录中至少说明：

| 内容 | 全队要回答的问题 |
|---|---|
| 任务 | 这问是解释、预测、评价还是决策？ |
| 输入 | 哪些数据和前问结果会进入？ |
| 输出 | 最终交付什么，单位和范围是什么？ |
| 变量 | 哪些已知、待估、由模型决定？ |
| 假设 | 为什么需要，取消后哪里改变？ |
| 关系 | 现实要求怎样变成公式？ |
| 目标 | 什么样的答案算更好？ |
| 约束 | 哪些条件绝不能违反？ |
| 参数 | 从哪里得到，数据能否确定？ |
| 验证 | 什么证据支持或推翻模型？ |
| 接口 | 结果怎样传给下一问？ |
| 边界 | 结论在哪些范围内有效？ |

不要求开局为每一项建立单独文件。内容能在共享记录中清楚找到即可。

## 四、模型比较

候选模型使用同一数据口径、划分和指标比较。保留主方案、必要的强备选和廉价审计基线；公平比较不等于平分算力，主方案应获得主要计算预算。

主方案增加的每一层复杂度都要回答：它修复了简单模型的哪个具体缺陷？如果没有可验证收益，退回简单模型。

优化问题先写清决策变量、目标、约束和取值范围，再选择求解算法。遗传算法、粒子群等只是求解工具，不是问题本身的数学模型。

## 五、全队口头检查

正式全量计算前，任意队员应能回答：

1. 这问为什么这样建；
2. 输入怎样一步步变成输出；
3. 关键假设和约束来自哪里；
4. 主模型为什么比基线合适；
5. 参数怎样得到；
6. 怎样的结果会说明模型有问题；
7. 输出怎样进入后一问；
8. 论文能说什么，不能说什么。

不能回答时，先补解释或用一个小样例走通，不用继续堆模型。

## 六、结果回审

得到结果后至少检查：

- 单位、符号、数量级和边界；
- 全部硬约束是否满足；
- 与简单基线或手算特例是否一致；
- 训练和验证是否按正确对象划分；
- 参数、停止条件和求解状态；
- 关键扰动下结论是否稳定；
- 前后问输入输出是否一致；
- 结论是否超出数据范围。

复核由未主做该部分的队员执行，并把问题写回共享记录。
