# 迁移到其他工具 / 机器的依赖与说明

本技能的核心是“数据 → 建模 → 求解 → 验证 → 结果包”。迁移后先检查计算环境；只有用户要求论文整合时才检查论文编译环境。

## 一、Python 依赖

```bash
pip install -r requirements.txt
```

核心包：numpy、scipy、pandas、matplotlib、scikit-learn、openpyxl、seaborn、statsmodels、pypdf、pdfplumber、pillow。

实际题目需要的额外求解器或库，应在任务表中单独记录并先做小规模测试。

## 二、外部程序

| 程序 | 作用 | 缺失后果 |
| :--- | :--- | :--- |
| xelatex + ctex（TeX Live / MiKTeX） | 编译中文 LaTeX 论文 | 论文 PDF 无法编译 |
| latexmk | 管理交叉引用和参考文献构建 | 含外部文献库的完整构建受限 |
| biber 或 bibtex | 处理参考文献 | 对应文献后端无法构建 |
| pdftoppm / mutool | PDF 渲染抽检 | 最终视觉检查受限 |
| draw.io 桌面版 CLI | 导出必要的流程图 | 流程图需交付源文件或采用可用降级方案 |
| LibreOffice（soffice） | 必要时重算 Excel 公式 | Excel 重算受限 |
| MATLAB | 执行 `.m` 代码（可选） | MATLAB 路线不可用 |

论文模板优先使用当届官方版本。缺少宏包、字体或引擎时报告具体阻塞，不静默改用不兼容模板。

## 三、中文字体与网络

- Windows 通常有宋体、黑体或微软雅黑；Linux/macOS 需确认 CJK 字体，否则图表和 PDF 可能缺字。
- 论文搜索工具需要访问 OpenAlex/AnySearch；离线时仅影响检索，不影响本地建模和已有文献使用。

## 四、迁移验证步骤

1. 安装 Python 依赖；
2. 运行 `python scripts/check_env.py`，确认核心包齐全；
3. 对当前题目先运行数据读取和最小模型 smoke test；
4. 开始全量计算并生成结果包；
5. 用户要求论文整合时，再检查 `xelatex`、`latexmk`、参考文献后端和 PDF 渲染工具，并先编译最小示例。

## 五、常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `ModuleNotFoundError` | Python 包缺失 | 安装 `requirements.txt` 并重跑 smoke test |
| 求解器超时/内存不足 | 规模或参数超预算 | 保存当前最佳结果，缩小规模或按阶段流程降级 |
| 论文 PDF 不编译 | 缺引擎、宏包或字体 | 诊断并修复环境，不把未编译源码当成完成 |
| 交叉引用/文献未解析 | 编译次数或后端不完整 | 使用 `latexmk` 和正确的 biber/bibtex 后端 |
| 图/PDF 中文乱码 | CJK 字体缺失 | 安装并指定可用中文字体 |
| 流程图不导出 | 未安装 draw.io CLI | 交付源文件或采用已验证的静态导出方案 |
| Skill 不加载子工具 | 当前 Agent 不自动发现子目录 | 手动读取对应 `tools/*/SKILL.md` |
