# 全队建模协议

文件名为兼容旧版保留，协议适用于全队，不只适用于思路负责人。

## 一、先说人话，再写公式

每问先用一段话回答：

1. 现实中要解决什么；
2. 已知什么；
3. 要求模型决定或估计什么；
4. 为什么现有信息可能够用；
5. 最终怎样判断答案可信。

公式出现后必须解释每个量、单位和现实含义。

## 二、分清六类内容

| 类型 | 含义 | 使用规则 |
|---|---|---|
| 题目事实 | 原题或附件明确给出 | 不能擅自改变 |
| 数据发现 | 对附件真实计算得到 | 数据处理变化后复算 |
| 领域依据 | 经核验资料支持 | 记录来源和适用范围 |
| 建模假设 | 为简化问题而采用 | 说明影响和检查方式 |
| 设计选择 | 阈值、权重、指标或算法选择 | 比较替代方案或做敏感性 |
| 未知项 | 现有证据不能确定 | 不假装已知 |

## 三、每一问的最小逻辑

共享记录中至少说明：

| 内容 | 全队要回答的问题 |
|---|---|
| 任务 | 这问是解释、预测、评价还是决策？ |
| 输入 | 哪些数据和前问结果会进入？ |
| 输出 | 最终交付什么，单位和范围是什么？ |
| 变量 | 哪些已知、待估、由模型决定？ |
| 假设 | 为什么需要，取消后哪里改变？ |
| 关系 | 现实要求怎样变成公式？ |
| 目标 | 什么样的答案算更好？ |
| 约束 | 哪些条件绝不能违反？ |
| 参数 | 从哪里得到，数据能否确定？ |
| 验证 | 什么证据支持或推翻模型？ |
| 接口 | 结果怎样传给下一问？ |
| 边界 | 结论在哪些范围内有效？ |

不要求开局为每一项建立单独文件。内容能在共享记录中清楚找到即可。

## 四、模型比较

候选模型使用同一数据口径、划分和指标比较。保留主方案、必要的强备选和廉价审计基线；公平比较不等于平分算力，主方案应获得主要计算预算。

正式完整赛题在冻结主路线前读取 `优秀论文资料路由.md`，检索 `摘要写作/摘要汇总.md` 并精读最相近的少数完整摘要。共享记录必须说明语料与本题的结构对应、可迁移方法、验证设计、不可照搬处，以及它使哪个候选被保留、改造或淘汰；同时保留至少一个不依赖优秀论文、由本题结构独立推出的强候选。

主方案增加的每一层复杂度都要回答：它修复了简单模型的哪个具体缺陷，或实际回答了哪项新增题意？预测价值、题意回答能力、解释价值、决策价值、风险分层、约束满足、稳健性和不确定性处理只是候选维度池；按题意选取与方案角色相关的维度判断“可验证收益”，不机械完成八项审核。

预测指标未提升不得单独触发淘汰。若复杂模型有额外题意回答、解释、决策、风险分层、约束、稳健性或不确定性价值，保留为扩展方案并降低结论强度；若只有轻微但不稳定的增益，保留为强备选或情景分析；只有相关主要维度均无实质增益时，才淘汰并退回简单模型。有统计显著性但没有实际决策或题意价值时，不得仅凭显著性升级为主模型。

后一问明确增加变量、因素、约束、误差或决策目标时，优先建立和评估对应扩展模型。交叉验证指标没有提升只说明不能声称预测改善，不能把后一问退化成上一问的重复答案。

进入每个递进子问题时都与上一问比较并重新识别结构，第三问作为高优先级检查点。若新增离散决策、组合约束、资源配置、时序、风险或不确定性，重新判断本问是否已由统计/预测升级为决策/组合优化或“统计 + 决策优化”。不硬编码第三问为 NP-hard；只有出现相应结构时，才提高 MILP、MINLP、CP-SAT、动态规划、网络优化和成熟启发式的优先级。

统计与决策串联时，先完成统计估计或风险建模，再定义决策变量、约束和目标并求解。预测模型若只是决策模型的输入层，不能只凭 CV、RMSE、NLL、Brier 等预测指标裁决整个方案。

优化问题先写清决策变量、目标、约束和取值范围，再选择求解算法。遗传算法、粒子群等只是求解工具，不是问题本身的数学模型。

## 五、全队口头检查

正式全量计算前，任意队员应能回答：

1. 这问为什么这样建；
2. 输入怎样一步步变成输出；
3. 关键假设和约束来自哪里；
4. 主模型为什么比基线合适；
5. 参数怎样得到；
6. 怎样的结果会说明模型有问题；
7. 输出怎样进入后一问；
8. 论文能说什么，不能说什么。

不能回答时，先补解释或用一个小样例走通，不用继续堆模型。

## 六、结果回审、冻结与解冻

得到结果后至少检查：

- 单位、符号、数量级和边界；
- 全部硬约束是否满足；
- 与简单基线或手算特例是否一致；
- 训练和验证是否按正确对象划分；
- 参数、停止条件和求解状态；
- 关键扰动下结论是否稳定；
- 前后问输入输出是否一致；
- 结论是否超出数据范围。

复核由未主做该部分的队员执行，并把问题写回共享记录。

完成回审后，若主方案同时满足以下七项，立即冻结并进入下一问：完整回答当前题目；核心假设无明显冲突；至少通过一种合适的样本外或稳健性验证；全部硬约束满足；最强备选没有足以改变主结论的明显优势；结果可复现；关键数值已独立回代检查。

冻结后的轻微问题、额外敏感性、边际改进以及更多 CV、Bootstrap、随机种子或备选模型只记录为局限或附录，不自动解冻。只有数据泄漏、目标定义错误、核心约束违反、明显计算错误、模型结构失效，或修正后可能改变主要结论时才解冻，并只重算受影响的链路。

验证服从计算预算：正式比赛优先保证所有子问题完整交付。若新增验证预计不会改变模型选择、主要结论、分组、排名或最终决策，应停止继续验证。
