# cumcm-modeling-lead｜国赛人机协同模型决策版

这套 Skill 以完整模型方案的设计与选择为核心。AI 帮助全队识别问题结构、生成单模型和组合方案、主动反驳、运行公平实验并给出有条件推荐；建模手决定现实目标、关键假设和最终冻结方案。

- 思路负责人主要维护全题逻辑和模型选择；
- 计算负责人主要维护数据、代码、求解和复现；
- 论文负责人主要维护表达、图表和前后一致；
- 每个人都必须能解释题目、模型、结果和局限。

## 使用体验

Skill 在开题、模型变化、长计算和关键结果节点输出已经填写的说明卡：

```text
现在做到：
这一步要解决：
为什么现在做：
我们已有：
这一步产出：
怎样算完成：
下一步：
```

说明卡不能空白；未知项必须写明原因和查证方法。之后再展开必要的数学内容。

## 核心流程

```text
1. 完整读题和附件，确认问题与数据结构
2. 拆分完整模型模块
3. AI广泛生成并反驳单模型和组合方案
4. 建模手确定进入实验的方案、目标和约束
5. 用相同口径公平实验，AI给出有条件推荐
6. 建模手冻结或退回修改
7. 对冻结模型正式计算、验证、绘图和写作
```

模型不是单个算法名。完整方案包含数据单位、标签或状态、特征、数学关系、目标约束、算法、决策规则、不确定性、解释和验证。自动排行只能产生推荐，不能替代建模手冻结。

严格记录模式可在正式预测、终稿图或论文前执行：

```bash
python scripts/model_decision_audit.py registries/项目状态.json --require-frozen
```

## 绘图

- SciPilot 方法是默认数据图入口：先分析数据和论证目标，再选择图型并视觉回审；
- Nature Figure 只增强少数已冻结的核心终稿图，执行源文件、字体、碰撞和多面板对齐审计；
- Draw.io 负责流程图、模型架构图和思维导图。

## 默认不会生成一堆空文件

新项目默认只维护：

- `全队建模记录.md`
- `AI使用记录.md`
- 题面、数据、建模与代码、结果、论文五个目录

真实计算开始后才创建运行记录；进入终稿时才创建结果、图表和论文结论的详细对应表。需要完整审计时可在初始化命令中添加 `--strict`。

## 开始使用

```text
使用 $cumcm-modeling-lead 处理这道国赛题。
先完整读取题目和附件，用中文说明当前事实和问题结构。
与我讨论完整模型模块、单模型和组合方案、假设、淘汰条件及验证。
AI可以推荐，但保持“待建模手裁决”；未经我确认不要冻结模型或写入终稿。
```

初始化轻量项目：

```bash
python scripts/init_competition_project.py D:/cumcm/projects/2026-C --competition CUMCM --problem C
```

需要严格记录时：

```bash
python scripts/init_competition_project.py D:/cumcm/projects/2026-C --competition CUMCM --problem C --strict
```

已有项目不会被覆盖。旧版的 `建模总控.md`、`模型合同.md`、`术语与符号表.md` 可以继续使用，Skill 不会再重复创建相同内容。

## 重要原则

- 先独立读题，再看优秀论文，避免被现成模型带偏；
- 完整赛题冻结路线前按 `references/优秀论文资料路由.md` 检索本地摘要语料，不让既有优秀论文提炼闲置；
- 主方案优先实现和全量计算，廉价基线通常不超过计算预算的一成；
- 先讲现实问题，再讲数学公式；
- 把题目事实、数据发现、假设、设计选择和未知项分开；
- 模型复杂度必须解决真实问题；
- 程序运行成功不等于模型正确；
- 优化结果必须代回全部约束；
- 同一对象的重复记录不能随意拆到训练集和测试集；
- 论文只能使用真实运行并验证过的结果；
- 时间不够时保住完整、可解释、可验证的方案。

所有题目产物写入题目项目目录，Skill 目录保持只读。许可证与来源见 [LICENSE](LICENSE) 和 [CREDITS.md](CREDITS.md)。
